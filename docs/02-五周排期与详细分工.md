# 移动互动课堂系统：5周开发排期与详细分工

## 第 1 周：环境搭建与“签到模块”演示闭环
【本周目标】：完成代码仓库初始化，全员本地环境跑通。实现“教师建课 → 生成课堂码 → 学生签到 → 大屏显示统计”闭环。
| 角色 | 本周具体任务 | 周五验收标准 |
| :--- | :--- | :--- |
| **PM（你）** | 1. 建好 Git 仓库，定好分支规范。2. 写 docs/api.yaml 接口契约（登录、建课、签到）。3. 本地写 SQL 脚本，造演示数据。4. 组织周四晚全流程彩排。 | 仓库代码合并无误，冒烟测试通过，能演示。 |
| **M1（学生端）** | 1. 建 Vue3 项目，写登录页、签到页。2. 对接后端登录接口、根据 6 位课堂码签到接口。3. 处理重复签到报错提示。 | 手机浏览器能打开 H5，输入 888888 签到成功。 |
| **M2（教师端）** | 1. 建 Vue3 项目，写教师登录页。2. 写建课页面，生成 6 位课堂码。3. 写签到列表页，展示已签到学生名单。 | 教师能登录、建课，看到动态增加的学生名单。 |
| **M3（后端 API）** | 1. 编写 user、classroom、checkin 表建表 SQL。2. 写登录 API（返回 Token）。3. 写建课 API、签到 API、签到名单查询 API。4. 配置全局跨域（CORS）。 | Postman / Swagger 能完整跑通上述 4 个接口。 |
| **M4（实时服务）** | 1. 搭建 Spring WebSocket 基础服务。2. 实现简单的“学生签到成功，推送给大屏/教师端”消息广播。 | WebSocket 连接建立成功，能收到签到推送。 |
| **M5（大屏+测试）** | 1. 建 Vue3 大屏项目。2. 大屏居中显示巨大课堂码。3. 实时接收签到推送，展示“应到/实到”人数和滚动名单。 | 投屏显示效果正常，数据能实时变化。 |

## 第 2 周：互动教学闭环（选人与单选答题）
【本周目标】：在签到基础上，完成“教师选人 → 发布单选题 → 学生答题 → 大屏显示正确率”。
| 角色 | 本周具体任务 | 周五验收标准 |
| :--- | :--- | :--- |
| **PM（你）** | 1. 更新接口文档（选人、发题、交卷、统计）。2. 检查各组员 PR，合并到 main。3. 编写全链路冒烟测试脚本。 | 各模块代码合并，主流程无阻塞 Bug。 |
| **M1（学生端）** | 1. 写答题页面（单选题 A/B/C/D 选项）。2. 对接提交答案接口，处理“已交卷”状态。 | 能接收题目，点击选项提交成功。 |
| **M2（教师端）** | 1. 写“随机选人”大转盘/动画页面。2. 写“发布练习”页面（选题、发布）。3. 查看答题进度页面。 | 能选人，能发题，能看到谁交了谁没交。 |
| **M3（后端 API）** | 1. 建 exercise、answer 表。2. 写选人 API、发布题目 API、提交答案 API。3. 写答题结果统计 API（正确率计算）。 | 答题逻辑无误，重复提交被拦截。 |
| **M4（实时服务）** | 1. 实现“教师发题”指令的实时推送。2. 实现“学生交卷”后的实时通知。 | WebSocket 消息类型丰富，推送稳定。 |
| **M5（大屏+测试）** | 1. 大屏展示当前题目题干。2. 实时展示选项分布柱状图、正确率百分比。3. 配合 PM 完成测试。 | 大屏能动态出柱状图，动画平滑。 |

## 第 3 周：抢答模块与“桌面图标”套壳
【本周目标】：完成抢答核心功能，并完成 Electron 桌面端套壳和 Capacitor 安卓 App 套壳。
| 角色 | 本周具体任务 | 周五验收标准 |
| :--- | :--- | :--- |
| **PM（你）** | 1. 统一发 app.ico 和 app.png 图标。2. 编写打包脚本，指导大家打包。3. 检查套壳后的包能否连上本地后端。 | 三个端都产出安装包，桌面有图标。 |
| **M1（学生端）** | 1. 开发“抢答”页面，毫秒级点击响应。2. 使用 Capacitor 将 H5 打包成 Android APK。 | 手机安装 APK 后，能进行抢答操作。 |
| **M2（教师端）** | 1. 开发教师“发起抢答”和倒计时页面。2. 使用 Electron 将教师端打包成 Windows exe。 | 双击 exe 图标打开，能发起抢答。 |
| **M3（后端 API）** | 1. 建 race 表。2. 写抢答 API（利用数据库时间戳保证绝对公平）。3. 写抢答排名查询 API。 | 接口能抗住多人同时请求，排序准确。 |
| **M4（实时服务）** | 1. 抢答开始瞬间的广播推送。2. 抢答首答成功的毫秒级截断与推流。 | 只有第一个请求被广播为大屏首答。 |
| **M5（大屏+测试）** | 1. 大屏抢答排名展示页（带动效）。2. 使用 Electron 将大屏打包成全屏 exe。3. 编写抢答并发测试脚本。 | 大屏全屏展示首答学生名字，无延迟。 |
