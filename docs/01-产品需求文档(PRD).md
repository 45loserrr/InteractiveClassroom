## 1. 背景与目标

### 1.1 背景

传统课堂提问方式存在三个痛点：**点名慢**（几十人点名耗时 5 分钟以上）、**参与度低**（只有少数学生回答问题）、**无数据沉淀**（谁答对、哪里错，全靠教师记忆）。

本项目用"学生手机 + 教室大屏 + 教师笔记本"三端联动，把签到、答题、抢答、统计压缩到**一次点击**内完成，所有数据自动落库并可视化。

### 1.2 产品目标（五周内）

1. 教师 **30 秒内**建课并投出课堂码，学生扫码/输码 **10 秒内**完成签到。
2. 一节课（45 分钟）内可完成签到 + 2 次随堂练习 + 1 次抢答，全程大屏实时刷新。
3. 课后可一键查看本节课签到率、正确率、排行榜，并可导出 Excel。
4. 全部终端在**局域网无外网**环境下可正常使用。

### 1.3 非目标（本期不做）

- 不做公网 SaaS 多租户、不做付费、不做移动端原生 iOS。
- 不做视频直播/录播。
- 不做与学校教务系统对接。

## 2. 用户角色

| 角色 | 特征 | 核心诉求 |
| :--- | :--- | :--- |
| 教师 | 40 岁左右，非技术型，临上课前 5 分钟才操作 | 打开就能用、按钮大、步骤少、出错有明确提示 |
| 学生 | 手机重度用户，课堂注意力分散 | 输码即进、无需注册、抢答反馈要"爽" |
| 旁听/管理者 | 教室后排通过大屏观看 | 屏幕字大、数据实时、无隐私泄漏（脱敏） |

## 4. 详细需求

### 4.1 基础教学

#### 4.1.1 登录（P0）

**描述**：教师使用账号密码登录教师端；学生输入"学号 + 姓名 + 6 位课堂码"直接进入课堂，无需注册。

**规则**
- 登录成功返回 `token`（JWT，有效期 12 小时）与 `role`。
- 学生首次进入时自动在 `user` 表建档（`role=student`）。
- 密码错误 5 次锁定 5 分钟（P1 可选，最简实现仅提示重试）。
- 未登录访问业务接口返回 `401`。

**验收**
- 输入正确账号密码可进入教师端首页，刷新页面登录态保持（localStorage）。
- 输入错误密码给出"账号或密码错误"，不暴露账号是否存在。

#### 4.1.2 创建课堂（P0）

**描述**：教师在教师端点击"新建课堂"，填写课程名/班级，系统生成 6 位数字课堂码。

**规则**
- 课堂码 6 位纯数字，全局唯一，同一时间只有一个进行中的课堂码可用。
- 课堂状态：`pending`（待开始）/ `ongoing`（进行中）/ `closed`（已结束）。
- 结束课堂后课堂码失效，学生再进入提示"课堂已结束"。

**验收**
- 建课成功后大屏立即显示 6 位码（字号 ≥ 200px，10 米可辨识）。

### 4.2 互动模块

#### 4.2.1 签到（P0）

**描述**：学生输入课堂码后点击"签到"，大屏实时显示已签到人数与滚动名单。

**规则**
- 同一学生对同一课堂只能签到一次，重复签到返回业务码 `1001` 并提示"你已签到"。
- 签到窗口可关闭（教师手动截止），截止后签到返回 `1002 签到已结束`。
- 大屏展示：应到人数、实到人数、签到率、最近 5 名签到学生（滚动）。

**验收**
- 学生签到后 ≤ 1 秒内大屏人数 +1，名单更新。
- 断网后恢复，学生重新签到不重复计数。

#### 4.2.2 随机选人（P0）

**描述**：教师点击"随机选人"，从已签到名单中抽取 1 人（可选 1~5 人）。

**规则**
- 只从已签到学生中抽取，签到人数为 0 时提示"暂无学生可抽"。
- 前端播放 ≥ 2 秒滚动动画，最终结果与后端返回一致。
- 可配置"不重复抽取"（同一节课内已抽中者不再抽）。

**验收**
- 连续抽 10 次，结果均在后端名单内且无空结果。

#### 4.2.3 单选答题（P0）

**描述**：教师从题库选题或直接输入题干/选项发布，学生在手机端点选 A/B/C/D 提交。

**规则**
- 一题一发布，发布后学生端 ≤ 1 秒内收到题目（WebSocket）。
- 学生只能提交一次；重复提交返回 `2001 已提交`。
- 教师端实时显示"已交 X / 应到 Y"，大屏实时显示选项分布柱状图与正确率。
- 教师点击"公布答案"前，学生端不展示对错。

**验收**
- 30 人同时提交，正确率统计误差为 0（与数据库统计一致）。

#### 4.2.4 多选答题（P1）

**描述**：题干支持多个正确选项，学生可多选。

**规则**
- 判定规则：全选对为正确，漏选/多选均为错误。
- 统计维度增加"漏选最多选项"。

**验收**
- 正确答案 `A,C`，学生选 `A` 判错、选 `A,C` 判对。

#### 4.2.5 抢答（P0）

**描述**：教师发起抢答并倒计时（默认 10 秒），学生点击"抢答"，首个成功者在大屏高亮。

**规则**
- 公平性由**服务端数据库时间戳**判定，禁止依赖客户端时间。
- 并发情况下只有一条记录 `is_first=1`，其余为普通参与记录。
- 大屏 300ms 内展示首答学生姓名（脱敏：张*明）。
- 同一学生同一题只计一次抢答。

**验收**
- 30 人并发抢答压测，`is_first=1` 记录有且只有 1 条，首答与界面展示一致。

### 4.3 课堂氛围

#### 4.3.1 弹幕（P1）

- 学生发送短文本（≤ 50 字），大屏从右向左滚动。
- 频率限制：同一学生 3 秒内最多 1 条；敏感词过滤（黑名单替换为 `*`）。
- 教师可关闭弹幕开关。

#### 4.3.2 分组（P1）

- 教师按人数随机分组（2~6 人/组），或手动拖拽调整。
- 小组维度统计：签到、答题正确数、抢答成功数，形成小组积分榜。

### 4.4 数据看板（P1）

| 看板 | 指标 | 展示形式 | 数据来源 |
| :--- | :--- | :--- | :--- |
| 签到率 | 应到/实到/签到率 | 环形图 + 数字 | `checkin` |
| 正确率 | 单题正确率、课堂平均正确率 | 柱状图 + 折线 | `answer` |
| 排行榜 | 答题正确数、抢答次数、活跃度 | 横向条形图 Top10 | `answer` + `race` |
| 学情报告 | 学生个人历史、班级汇总 | 表格 + 可导出 | 聚合查询 |

**规则**
- 所有看板数据按课堂维度实时聚合，刷新间隔 ≤ 3 秒。
- 大屏展示姓名必须脱敏（张*明），教师端可看全名。

### 4.5 扩展功能（P1）

#### 4.5.1 题库管理

- 题目字段：题型（单选/多选）、题干、选项 A~D、正确答案、难度（易/中/难）、知识点标签。
- 支持 Excel 批量导入（模板见 `docs/` 后续补充），导入失败逐行报错。

#### 4.5.2 公告

- 教师发布公告（标题 + 正文 ≤ 200 字），学生端顶部横幅展示，大屏可轮播。

#### 4.5.3 导出 Excel

- 导出内容：签到明细、答题明细、排行榜。
- 文件名格式：`课堂名_课堂码_导出时间.xlsx`，中文不乱码（UTF-8 BOM）。

## 5. 关键流程

### 5.1 上课主流程（P0 闭环）

```
教师登录 → 新建课堂 → 大屏显示 6 位码
        ↓
学生输码进入 → 签到 → 大屏人数/名单实时变化
        ↓
教师随机选人（动画） → 发布单选/多选 → 学生作答 → 大屏正确率
        ↓
教师发起抢答 → 学生抢 → 大屏首答高亮
        ↓
结束课堂 → 数据看板 → 导出 Excel
```

### 5.2 异常流程

| 场景 | 期望行为 |
| :--- | :--- |
| 课堂码输错 | 提示"课堂码不存在，请核对" |
| 课堂已结束 | 提示"该课堂已结束" |
| 重复签到/重复交卷 | 友好提示，不产生脏数据 |
| 断网 30 秒 | 前端自动重连 WebSocket，期间操作给出"网络不稳定"提示 |
| 后端重启 | 前端重连后重新拉取当前状态，不丢已提交答案 |

## 6. 非功能需求

| 类别 | 指标 |
| :--- | :--- |
| 性能 | 单课堂 60 人；签到/答题接口 P95 < 300ms；抢答判定 < 100ms |
| 并发 | 30 人同时抢答不丢数据、不重复首答 |
| 兼容 | Chrome/Edge 最新版；Android 10+ 微信/浏览器；大屏 1920×1080 与 4K |
| 可用 | 无外网可运行；后端异常不崩溃（全局异常处理） |
| 安全 | 密码 BCrypt 存储；Token 鉴权；SQL 参数化防注入；姓名脱敏 |
| 可维护 | 分层清晰（controller/service/mapper/entity）；接口文档 Swagger 可访问 |

## 7. 数据字典（初版）

| 表 | 关键字段 | 说明 |
| :--- | :--- | :--- |
| `user` | id, username, password, real_name, role | 教师/学生账号 |
| `classroom` | id, name, code, teacher_id, status, started_at, ended_at | 课堂与 6 位码 |
| `checkin` | id, classroom_id, student_id, checked_at | 签到流水，唯一约束防重复 |
| `exercise` | id, classroom_id, type, stem, options, answer, status | 题目与发布状态 |
| `answer` | id, exercise_id, student_id, content, is_correct, submitted_at | 作答明细 |
| `race` | id, exercise_id, student_id, is_first, raced_at | 抢答流水，时间戳判序 |

完整 DDL 见 `backend/src/main/resources/db/schema.sql`。

## 8. 验收标准（答辩前自检）

- [ ] 六端环境按 README 从零可跑通（换一台干净电脑验证）。
- [ ] P0 闭环全程无阻塞 Bug：建课 → 签到 → 选人 → 答题 → 抢答 → 看板。
- [ ] 30 人并发签到/抢答压测报告已产出（`docs/` 下）。
- [ ] Swagger 文档可访问且与实际接口一致。
- [ ] 大屏姓名脱敏、无真实学号泄露。
- [ ] 仓库无密码/Token/本地配置泄露，`main` 分支可编译。
